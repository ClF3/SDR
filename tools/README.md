# Tools

Developer utilities for packet decoding, captures, spectrum plotting, and link diagnostics.

## Network Probe

Use this before starting the Raspberry Pi Web backend when debugging the real
AC920 link:

```sh
python tools/network_probe.py <ac920-ps-ip>
```

Expected successful path:

1. TCP connects to `<ac920-ps-ip>:9000`.
2. `hello` and `ping` get JSON Lines responses.
3. UDP status arrives on `9003`.
4. `set_rx` starts IQ UDP on `9001`.
5. `set_psd` starts PSD UDP on `9002`.

If step 1 fails, the FPGA bitstream alone is not enough: the AC920 PS must also
run the TCP/UDP bridge firmware or Linux application.

For local RTL/network co-simulation, start the Verilated endpoint first:

```sh
cd fpga
./scripts/run_cosim_server.sh --bind 127.0.0.1 --control-port 9000
```

Then run the normal Raspberry Pi backend and frontend. The backend still talks
to TCP/UDP sockets, but the IQ UDP stream is generated by Verilated FPGA RTL.

One local bring-up sequence is:

```sh
python -m venv /private/tmp/sdr-cosim-venv
/private/tmp/sdr-cosim-venv/bin/python -m pip install -e ".[dev]"
cd rpi/frontend && npm ci
```

In three terminals:

```sh
cd fpga && ./scripts/run_cosim_server.sh --bind 127.0.0.1 --control-port 9000
/private/tmp/sdr-cosim-venv/bin/python -m sdr_backend --config rpi/backend/config/dev.yaml --host 127.0.0.1 --port 8080
cd rpi/frontend && npm run dev -- --host 127.0.0.1
```

Open `http://127.0.0.1:5173/`, keep AC920 host as `127.0.0.1`, then press
Connect and Start RX.
